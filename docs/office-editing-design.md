# 办公与电子书格式原格式编辑设计

状态：待维护者审阅。2026-11-25。

## 1. 目标与原因

FreeFolio 现在只把 Word、Excel、PowerPoint、OpenDocument、RTF、电子书和邮件读成 Markdown 并锁定只读（`internal/app/formats.go`），用户只能另存为 Markdown 副本。维护者要求：这些文件能在 FreeFolio 中直接编辑，并按原格式写回原文件，且不损坏原文件。另存为 Markdown 副本保留。

“不损坏”的含义：

- 用户没改的内容，包括样式、页眉页脚、图片、批注、公式、宏和未识别的部分，保存后保持原样（逐字节或语义等价）。
- 改过的内容按用户改动写回，并沿用原段落或单元格的样式。
- FreeFolio 无法安全表达的改动，保存时报错并说明原因，不写入原文件，不静默丢弃内容。

## 2. 范围

按维护者 2026-11-25 的决定，分两步实施。

### 第一步：基于 XML 或文本的格式（本设计）

| 类别 | 扩展名 | 可编辑内容 |
| --- | --- | --- |
| Word | `.docx` `.docm` `.dotx` `.dotm` | 正文段落、标题、列表项、表格单元格 |
| Excel | `.xlsx` `.xlsm` `.xltx` `.xltm` | 单元格值，在表格末尾追加行和列 |
| PowerPoint | `.pptx` `.pptm` `.potx` `.potm` `.ppsx` | 已有文本框内的段落、备注 |
| OpenDocument | `.odt` `.ott` `.ods` `.ots` `.odp` `.otp` 及单文件版 `.fodt` `.fods` `.fodp` | 与对应的 Word、Excel、PowerPoint 相同 |
| RTF | `.rtf` | 正文段落；表格单元格文字 |
| AbiWord | `.abw` | 正文段落 |
| EPUB | `.epub` | 各章节的段落、标题、列表项、引用、表格单元格 |
| FictionBook | `.fb2` | 段落、标题 |
| 邮件 | `.eml` | 主题、正文 |

### 第二步：二进制格式（单独评估）

二进制格式包括：`.doc` `.dot` `.xls` `.xlt` `.ppt` `.pps` `.pot`，WPS 的 `.wps` `.wpt` `.et` `.ett` `.dps` `.dpt`，以及 `.msg` `.mobi` `.azw` `.azw3` `.prc`、iWork、OFD、XPS。

第二步用真实样例逐个实测候选库：`antoema342/go-spreadsheet`、`talentformula/msdoc`、`abemedia/go-cfb`。只有满足以下全部条件的格式才开放编辑：

- 改字后，Office 和 WPS 打开不报错、不提示修复。
- 未改的内容不变。
- 许可证可以接受。

实测不通过的格式继续只读，界面说明原因。第二步的实测记录另写，本文不覆盖。

### 不做（非目标）

- 不编辑字体、颜色、字号、对齐等排版属性（维护者选了“文字与结构”）。
- 不增删工作表、幻灯片、EPUB 章节。不在电子表格中间插入或删除行列，因为这需要改写公式引用。
- 不编辑页眉、页脚、脚注正文、批注正文、文本框之外的形状和图表。
- 日历、名片、思维导图、Jupyter、SQLite、压缩包等其他转换格式保持只读。

### 反目标（技术上能用也算失败）

- 保存后 Office、WPS 或 LibreOffice 打开时提示文件损坏或需要修复。
- 未改动的内容丢失或被改写，例如样式表被重新序列化后丢失未知元素。
- 自动保存把用户误触的改动写进原文件，且无法找回原版本。

## 3. 方案比较

| 方案 | 做法 | 取舍 |
| --- | --- | --- |
| A 自写局部替换 | 读取时记录每个块在源文件中的字节范围；保存时只重写改过的元素，其余字节原样复制 | 无新依赖，保真度最高；每种格式都要写回代码 |
| B 引入第三方库 | OOXML 用 excelize、spine、godocx 等，其余自写 | excelize 成熟，但会重新序列化工作表 XML；spine 和 godocx 只有几颗星；对象模型和编辑器之间要再做一层映射 |
| C 混合（已选） | 以 A 为主；邮件的 MIME 解析和编码复用 `github.com/emersion/go-message`（MIT，460 星） | 邮件的字符集、传输编码和头部折行交给成熟库，其余与 A 相同 |

维护者选定方案 C。spine、godocx、excelize 只作为设计参考，主要参考“未读部分逐字节写回”“已读未改部分原样输出”这两条往返保存原则，不作为依赖引入。

## 4. 总体设计

```mermaid
flowchart LR
  F[原文件字节] -->|formats.OpenEditable| E[Editable: 片段列表 + 原包]
  E -->|每个片段的 Markdown| I[editor.ImportMarkdown]
  I --> D[编辑器文档<br/>块 ID → 片段]
  D -->|保存: 按块 ID 比较| P[保存计划<br/>保留 / 改写 / 新增 / 删除]
  P -->|Editable.Save| N[新文件字节]
  N -->|重新读取并核对| V{一致?}
  V -->|是| W[原子写入原文件]
  V -->|否| X[报错，不写入]
```

图中箭头表示数据流向。

### 4.1 formats 包：可编辑读取与写回

`internal/formats` 新增可编辑接口。该包只依赖 `internal/document` 模型，不依赖界面：

- `OpenEditable(name string, data []byte) (Editable, error)`：只对第一步的格式返回结果。其余格式返回 `ErrUnsupported`，并附带不能编辑的原因（加密、数字签名、二进制格式等）。
- `Editable.Segments()`：按文档顺序返回片段。每个片段包含：
  - 自己的 Markdown；
  - 是否可编辑。FreeFolio 自己生成的标签，如“幻灯片 3”“（空工作表）”“另有 N 行未显示”和附件列表，不可编辑；
  - 定位信息，由格式自己解释，例如 XML 部件名加元素的字节范围、工作表单元格坐标。
- `Editable.Save(plan []Piece) ([]byte, error)`：`Piece` 有两种。一种保留原片段 i；另一种给出新内容（`[]*document.Block`），并指明它替换哪个原片段，或者插在哪个片段之后。新内容的样式模板取自被替换的片段，插入时取前一个同类片段。

现有转换器与可编辑读取共用同一遍解析：`mdWriter` 在输出每个块前记录定位信息，避免同一格式维护两份读取逻辑。只读路径（`Convert`）的输出保持不变。

### 4.2 包级写回规则

- **ZIP 容器**（OOXML、ODF、EPUB）：用 `zip.Writer.Copy` 按原顺序原样复制未改动的条目，不解压也不重新压缩。只重写改动过的部件，并保留原压缩方式。ODF 和 EPUB 的 `mimetype` 保持第一个条目，且不压缩。
- **XML 部件**：用 `xml.Decoder.InputOffset` 记录元素的起止字节，原样复制未改元素的字节，只替换改动元素的字节。不用 `encoding/xml` 重新序列化整个部件。
- **单文件格式**（RTF、FODT 等、ABW、FB2、EML）：同样按字节范围拼接。

### 4.3 各格式写回要点

- **Word / ODT**：
  - 段落：保留原 `w:pPr` / 段落属性；按编辑器的文字样式重新生成文字片段，基础样式取原段落第一个文字片段。粗体、斜体、删除线按编辑器的样式开关。链接复用已有的关系 ID，没有时新增关系。
  - 标题级别：映射到文档已有的标题样式。
  - 列表项：新增时复制相邻列表项的编号属性。
  - 表格：改单元格文字；增删行时复制相邻行。
- **Excel / ODS**：
  - 按坐标改单元格，保留样式属性 `s`。数字仍写成数字，其余写成内联字符串，不改共享字符串表。
  - ODS 遇到 `number-columns-repeated` 时，先拆分再修改。
  - 只允许在末尾追加行列。
- **PowerPoint / ODP**：在原文本框内改段落、增删段落，保留 `a:pPr`。
- **RTF**：保留每段开头的控制字，正文按原代码页转义；原代码页无法表示的字符写成 `\uN?`。
- **EPUB / FB2 / ABW**：替换改动元素的内部内容，保留元素自身的标签和属性；新增元素复制相邻同类元素的标签和属性。
- **EML**：
  - 用 go-message 解析各部分；改动主题和正文所在的部分，按原字符集和传输编码重新编码。原字符集无法表示的字符改用 UTF-8。
  - `multipart/alternative` 的纯文本和 HTML 两部分一起更新：HTML 部分按 EPUB 规则改元素，纯文本部分由编辑后的内容生成。
  - 其他部分（附件、内嵌图片）按字节原样保留。

### 4.4 保存时必须报错而不写入的情况

- 改动的段落含有无法映射的行内内容：图片、域代码、修订标记、批注范围、公式、内容控件、脚注引用。
- 改动了 FreeFolio 生成的标签片段；改动了公式单元格的值；在表格中间增删行列；改动了合并单元格所在表格的结构。
- 文件有数字签名（OOXML `_xmlsignatures`、ODF `documentsignatures.xml`、S/MIME 邮件）、已加密或有 DRM。这类文件在打开时就保持只读，并说明原因。
- 写回后重新读取新字节，逐片段核对纯文本，与预期不一致。

报错信息说明是哪一段、为什么不能保存，并提示用户：可以撤销改动，或另存为 Markdown 副本。

### 4.5 app 层接入

- `document` 增加可编辑的转换文件状态，保存 `Editable`、块 ID 到片段的映射和原文件指纹。现有 `converted` 文档的只读路径不变。
- 打开时，这些格式默认处于“锁定（只读）”状态（`ReadOnly = true`，`Locked = false`）。用户用现有的“解锁文档”命令开始编辑，避免误触直接改原文件。（我的决定，维护者可改。）
- 保存与自动保存复用现有 `write` 和后台保存流程。写入前比较原文件指纹（修改时间、大小），检查外部修改；写入使用 `vault` / `fsutil.WriteFileAtomic`。
- 每次会话首次覆盖原文件前，把原文件字节存为一个保留版本：版本历史按原扩展名保存二进制快照；版本面板对这类文件只提供“恢复”，不显示文本差异。空间外的文件不使用版本历史，改为在同目录的系统目录中保留恢复副本。（具体落点由实施时决定。）
- 格式角标显示“Word · 只读”或“Word · 可编辑”；不能编辑的格式在角标提示中给出原因。

## 5. 约束

- 纯 Go，无 cgo，不引入 WebView。
- 新依赖只有 `github.com/emersion/go-message`。按项目约定：选用发布超过 7 天的版本，运行 `tools/update_go_inventory.py` 并核对许可。
- 界面文字用 `i18n.T` 并补英文。
- `View` 中不做文件读写，读取和保存放在 goroutine 中。
- 每种格式都要有往返测试：
  - 不改内容保存，结果字节与原文件相同；
  - 改一段，只有该段变化，其余部件逐字节相同；
  - 新增和删除段落；
  - 必须报错的各种情况。
- 测试夹具用代码生成或使用可公开许可的最小样例，二进制夹具按例外清单登记。
