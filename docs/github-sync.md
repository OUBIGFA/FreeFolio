# GitHub 仓库空间同步

## 目标与边界

导入已有 Git 仓库作为空间，登录 GitHub 并授权仓库后，直接提交、推送和拉取。尚未使用 Git 的空间也可直接创建私有仓库。支持完整的手动操作、计划同步、OneBot 提交说明、冲突解决和恢复。界面使用现有 Go + MyGo；优先复用本机 Git，没有时按需校验并安装 MinGit，不改变系统 PATH。

点击“连接 GitHub”后，在系统浏览器中登录并授权即可。FreeFolio 调用 Git Credential Manager（GCM）的官方登录流程，不要求注册 GitHub App、配置 Client ID 或填写令牌。优先使用电脑已有的兼容 GCM，缺少时自动下载官方组件并核对 SHA-256，不修改系统 PATH 或全局 Git 设置。

## 使用方式

设置中的 GitHub 同步页管理账号、空间、当前分支、远端、变更和同步计划。选择空间后检查仓库，明确绑定远端与分支。同步默认关闭；开启和保存设置不立即执行，也不补跑错过的任务。定时任务需要程序运行，最小化到托盘可继续运行。

同步动作包括双向同步、仅拉取、仅提交并推送；另外保留独立的提交、推送、拉取按钮。每个空间保存自己的计划、账号和 OneBot 模型。计划支持间隔、每日指定时间、保存后延迟、启动时执行、每日上限和失败重试。

“保存后同步”默认关闭，开启后才能编辑“保存后等待（秒）”。0 秒表示保存后立即同步，1–3600 秒表示等待最后一次保存后的指定时间。关闭并保存设置后取消尚未执行的保存触发任务，定时和手动同步继续按原设置工作。开启开关或保存设置本身不会触发同步，已有空间保留原来的开关和等待时间。

提交说明支持手写、固定模板、OneBot 自动生成。OneBot 使用已有连接和模型，不改变聊天选择。仅发送本轮选定文件的改动与文件名；无变更不调用模型。大改动按有界输入处理并明确说明省略；失败显示原因，只有用户配置允许时才回退模板。手动生成可以预览修改，自动任务使用生成结果。首次启用自动生成时告知内容传输与可能计费。

## 为普通空间创建私有仓库

1. 连接 GitHub 账号，选择尚未使用 Git 的空间，点击“创建私有仓库”
2. 检查账号、仓库名称和待上传文件，只勾选本次要上传的文件
3. 点击“创建私有仓库并上传”，在所选个人账号下创建私有仓库并上传选定文件

准备阶段只初始化本地 Git 元数据，不创建远端仓库，也不上传文件。已有 Git 历史、远端或已暂存内容的空间不走此流程。文件列表遵守 Git 忽略规则，敏感目录和配置默认不选；确认前文件有变化时要求重新检查。

仓库固定为私有，不提供公开选项。创建成功后先保存绑定，再提交并上传；上传失败会保留绑定及已生成的提交，可通过“提交”或“推送”继续。初始同步方向为“提交并推送”，自动同步保持关闭。创建请求的结果不明确时，先到 GitHub 检查同名仓库，程序不会自动重复创建。

## 安全与恢复

“同步排除”提供文件与文件夹清单，可筛选和勾选，也可随时重新打开取消勾选。规则写入根目录 `.gitignore` 的 FreeFolio 标记区，原有手写规则保持不变。排除文件夹时包含其中的文件；取消本页的规则不会撤销其他手写忽略规则。

对已跟踪文件，保存排除会停止跟踪并保留本地内容，工作区显示“保留本地，待从云端移除”。下一次选定提交及推送后，从云端当前版本移除，历史提交仍保留。文件有已暂存编辑时先处理暂存内容，外部修改了忽略规则时重新读取后再保存。尚未提交排除时取消勾选，会恢复原跟踪状态，不丢失本地编辑。

Windows 上，GCM 将令牌加密保存在 FreeFolio 配置目录的 `credentials/gcm`，使用系统 DPAPI；macOS 使用系统钥匙串，Linux 使用 Secret Service。每次连接使用独立的 FreeFolio 凭据名称，断开不会删除其他 Git 工具的账号。账号身份经 GitHub 核实后才显示连接成功。登录取消、失败或凭据失效会显示错误，后台同步不自动弹出登录窗口。HTTPS Git 凭据通过受限凭据助手传递，只回应 github.com 上选定的仓库。

仓库操作串行执行，保留用户暂存区；自动任务遇到用户已暂存内容时暂停并提示。提交、推送不强制改写历史。绑定的远端、分支或空间根目录改变时需要重新检查。SSH 仓库保留原有 SSH 认证，不因网页登录而改写远端。

拉取在独立工作目录中合并，冲突不污染正在编辑的原文件。冲突面板可查看版本、选择本地或远端、编辑文本并完成合并，也可取消合并。应用合并前重新检查原仓库 HEAD、暂存区和工作区；备份受影响文件，删除走系统回收站。二进制和不支持文本合并的文件提供完整版本选择，不把冲突标记写入白板或附件。

同一空间不能同时参与网盘同步和 Git 自动同步。网络、AI 请求、Git 和扫描均在后台执行；界面不在每帧遍历目录。退出取消任务，冲突与已产生的本地提交保留，下次可以继续。

## 复用依据

- Git for Windows / MinGit 2.56.1.windows.1，Git 主体 GPL-2.0；可选包保留自己的许可文件
- Obsidian Git 2.44.0（MIT）作为工作流参考，没有引入 TypeScript 或运行时
- Git Credential Manager 3.0.2（MIT）的浏览器 OAuth 授权和系统凭据存储；现有 HTTP 和 OneBot 接口继续复用
- 现有云同步的不开启补跑、备份和活动编辑保护规则

## 验证

隔离临时仓库和本地 bare remote 验证真实 Git 行为；本地 HTTP 服务与凭据助手子进程验证登录结果、取消、失败、下载和 AI 输出。官方 GCM 程序在隔离凭据目录中验证存储、读取与断开，使用合成测试令牌，不接触用户账号。原生无窗口测试覆盖登录按钮、设置、调度和冲突入口。真实 GitHub 浏览器登录仍由用户本人完成，不以本地模拟代替账号验收。

## 登录与授权

1. 打开“设置 → GitHub 同步”，点击“连接 GitHub”
2. 首次使用时等待组件准备完成，浏览器将自动打开 GitHub
3. 登录并授权 Git Credential Manager，返回 FreeFolio 查看账号
4. 选择空间并检查仓库，选择同步账号和规则后保存设置

授权页面显示 Git Credential Manager 的应用身份。它按上游流程申请 `repo`、`gist` 和 `workflow` 权限，权限范围由 GitHub 页面展示；FreeFolio 只对明确选择的空间执行同步。组织仓库可能需要管理员批准或 SSO 授权。“管理仓库授权”打开 GitHub 的应用授权页面；受保护分支遵守 GitHub 的推送限制，不绕过保护。

“断开账号”移除 FreeFolio 自己保存的登录，GitHub 端的应用授权可在上述页面撤销。较早构建中通过自注册应用连接的账号需点击“连接 GitHub”重新授权一次，同一账号的空间绑定继续保留。

## 文件与恢复范围

默认不选择 `.freefolio`、`.arcmd`、`.local`、`_temp`、`credentials`、`node_modules` 和 `.env` 文件；Git 忽略规则仍生效。其他变更可在手动提交列表中选择。自动同步遇到用户暂存的文件会暂停，避免将其他工作的暂存内容一起提交。

LFS 仓库使用原生 Git LFS 处理附件，Windows 缺失时按需下载校验后的 Git LFS 3.8.1；不把 LFS 指针误报为图片或视频已下载。系统 Git 的 SSH 配置继续生效，网页登录只授权 HTTPS 仓库访问。

原仓库发生分支、远端或根目录变化后，应重新检查并绑定。合并冲突保存在配置目录的 `git-sync-state`，重新打开设置并检查仓库可继续。合并应用失败时恢复已替换文件；外部程序又修改了这些文件时停止恢复并保留副本，防止覆盖新内容。恢复目录按仓库隔离，提供“打开 Git 恢复备份”入口。
