# AI 文档编辑设计

状态：已确认实施，包含 OneBot 与多供应商扩展。2026-11-20。

本文记录已授权的实施范围；验证和交付状态见实施计划。目标是一次交付完整的文档编辑工作流：用户提出修改要求，AI 生成可定位的修改，用户直接应用或比较方案，并能够继续修改、撤销、保存和恢复。

## 1. 交付目标

FreeFolio 的 AI 同时支持问答和文档编辑。选区操作与侧栏对话使用同一套修改、校验和恢复机制。

已经明确的需求：

- 选中文字后用自然语言要求改写。
- 可以生成完成后直接修改，也可以生成几个方案，选择后应用到对应原文。
- 以使用方便、接入轻量、修改可靠为依据，组合开源项目的适用机制。
- 按完整工作流交付，不把格式、冲突处理或撤销留作后续补充。

为使流程完整，本设计建议同时覆盖：章节和全文编辑、同一文档多处修改、明确指定文档的编辑、逐处审阅、连续追问修改、版本恢复，以及任务完成与保存状态。明确选定的多文档任务也进入本设计的交付范围；这是对原始选区需求的扩展建议，不意味着普通问答可以自动修改整个空间。

开发可以按依赖顺序进行，最终按本文统一验收。中间构建不作为功能交付完成。

## 2. 方案选择与最终约束

按用户 2026-11-20 的纠正，文件编辑工具直接移植成熟开源实现。采用 MIT 的 [OpenCode](https://github.com/anomalyco/opencode/tree/85951cb08614dfe6443905552cae49d59d2d6615)，固定提交、保留许可证和来源哈希。原生 Go 移植其 `edit` 匹配算法、`patch` 解析与应用算法、`read / edit / write / patch` 工具接口。不能以自定义 JSON 修改协议替代这些工具。

FreeFolio 只承担必要的宿主连接：选区/文档范围、快照、富文本映射、审阅、撤销、持久恢复及原子保存。来源和具体差异见 [OpenCode 移植记录](../third_party/opencode/README.md)。

界面保留原 AI 问答的时间线、流式 Markdown 和引用体验。更名为 OneBot；参考 OpenCode/Zed/Codex 的对话操作逻辑，输入区保留附件入口、合并的供应商/模型菜单和发送按钮。范围、候选数量、直接修改和供应商管理进入菜单，不在对话页铺设设置面板和胶囊按钮。修改摘要与展开后的差异附在回答下方。

## 3. 完整功能范围

| 能力 | 交付行为 |
| --- | --- |
| 选区编辑 | 支持句内选区、跨段选区和连续块选择；请求开始后保留原目标，不随当前光标变化 |
| 章节与全文编辑 | 可以指定当前章节、整篇当前文档，或者明确引用的其他文档；展示实际编辑范围 |
| 对话中执行修改 | 支持“把第二节改得简洁一些”“统一这篇的术语”等指令；在回答中展示实际修改结果 |
| 常用写作动作 | 润色、纠错、精简、扩写、翻译、调整语气、总结、续写和自定义要求 |
| 内容操作 | 替换、前后插入、删除指定内容、调整段落或列表结构；明确要求时新建文档并写入 |
| 多处修改 | 同一指令可生成多个修改点，能够定位、逐处接受、逐处拒绝或一次接受全部 |
| 多个方案 | 默认提供三个候选，可选择两个至五个；预览、查看差异、继续调整某个候选后应用 |
| 直接修改 | 用户选择直接修改或明确要求直接应用后，完整生成并通过校验的修改自动应用；成功后可立即撤销 |
| 审阅后应用 | 候选留在独立草稿中；显示原文、建议内容和真实差异；应用前不改变正文或触发正文自动保存 |
| 连续修改 | 可以针对候选说“再短一点”，也可以在应用后继续修改新内容；明确显示当前修改所基于的版本 |
| 多文档任务 | 只修改本次明确选定的文档；按文档展示修改点、应用状态、保存状态和恢复入口 |
| 操作可恢复 | 文档撤销/重做、任务内回退与修改前的持久快照共同覆盖日常纠正和重启后的恢复 |
| 完整状态 | 生成中、已停止、失败、待审阅、部分应用、已应用未保存、已保存、原文已变化均有明确结果 |

读取其他笔记作为参考，与允许修改这些笔记分开。可写范围由用户本次选择及明确指令确定。范围不明确时在现有界面选择目标，不能仅凭模型猜测扩展。

本设计聚焦文档内容及明确请求的新文档。文件批量移动、系统命令、安装扩展和操作任意本机路径不属于这个功能的依赖。

## 4. 用户操作规则

### 4.1 入口与目标

- 选区操作、编辑器菜单、命令入口及现有 AI 侧栏都可以启动修改。
- 调出输入框前捕获目标；输入框获得焦点不会丢失原选区。
- 在发出请求时显示“选中文字”“当前章节”“整篇文档”或具体文档列表。
- 分屏、切换空间或切换文档不改变已经开始的任务目标。任务结果不能写入后来获得焦点的文档。
- 正在输入法组词时不读取临时文字作为提交内容，也不将 AI 修改插入正在组词的范围。完成提交后再捕获或应用。
- 编辑只读文档、加载失败文档或已有未解决文件冲突时，说明原因并保留候选。

### 4.2 两种应用方式

审阅模式生成独立草稿，支持查看差异、选择候选、继续调整、逐处应用和全部应用。

直接修改模式也先在内存中构建完整提案。请求成功结束、输出合法、目标仍有效、恢复副本已建立后，自动应用到指定文档。用户不需要再次确认已经选择的直接修改操作。

普通问答不因回答中出现 Markdown 或代码块而写入文档。进入编辑流程必须有编辑入口、编辑模式或明确的编辑指令。

### 4.3 候选与连续指令

- 同一批候选基于同一份原文快照，区别是改写内容或用户指定的表达方向。
- 候选通过独立请求或服务支持的等价结构化返回生成；不依赖某一家服务的多候选参数。限制同时进行的请求数量，保留单个候选的失败和重试状态。
- 增加方案会增加请求量。界面展示候选数量和生成状态，不因一个候选失败丢弃其余已完成结果。
- 在预览中切换方案不修改正文。继续调整某个候选也只修改该候选。
- 应用后，以新的文档状态开始下一轮。其他基于旧原文的候选须重新校验，不能直接覆盖已应用结果。
- 停止会取消本任务的全部生成请求。迟到的结果不能重新激活已取消任务或执行写入。

### 4.4 审阅粒度

差异由程序比较原文与提案计算，不使用模型声称的差异作为事实。

普通文字显示增加和删除。结构变化显示受影响的段落、列表项、表格单元格或完整结构。有关联的操作组成一个审阅单元，例如一个表格结构变更及其单元格调整，不能只接受其中会使文档无效的部分。

支持前后定位、逐处接受/拒绝、全部接受/拒绝。部分应用后更新其余修改点的位置与有效性；已经应用或拒绝的修改不会被重复执行。

## 5. 目标定位和修改协议

### 5.1 本地捕获目标

每个任务记录文档身份、空间身份、文档实例代次、内容版本，以及所选块的稳定 ID、块内 UTF-16 边界和原始结构。必要的前后文只供模型理解，不自动获得可写权限。

模型使用本次提供的文档路径，通过 `read` 读取可写快照，通过 OpenCode 文件工具生成修改。内部块标识仅供宿主保存和定位，不暴露为模型修改协议。越界路径、歧义匹配和无效补丁直接报错。

FreeFolio 的 `LeafByID` 可在其他段落增删后重新找到目标。校验还必须覆盖目标内容、格式、顺序和必要的父级结构：文字相同但段落已移动、表格已拆分或格式已改变，不能仅凭文字匹配视为未变化。

允许目标之外的普通编辑继续进行。对同一目标发生的修改，只自动重定位可证明不相交的变动；有重叠或定位不确定时保留提案，显示冲突并允许基于最新内容重新生成。不能在全文模糊查找一段近似文字后替换。

### 5.2 复用 OpenCode 文件工具

- `read(path, offset, limit)`：读取带行号的快照。选区模式只暴露选中文字；读取其他文档作为参考不授予修改权限。
- `edit(path, oldString, newString, replaceAll)`：采用上游精确替换、Unicode 标点与行尾空格匹配顺序，以及唯一匹配检查。保留未涉及的 LF/CRLF 和 BOM。
- `write(path, content)`：替换选定快照的内容，或写入明确指定的新文档路径。
- `patch(patchText)`：采用上游补丁格式、上下文和 EOF 定位规则；完整批次准备通过后才更新快照。

这些工具修改隔离快照，最终结果由 FreeFolio 比较并转换为本地编辑器事务。没有 `propose_edits`、`edit_targets` 或要求模型构造原生块的协议。不支持工具调用的模型可以返回同一套 OpenCode 补丁文本；解释性回答和不完整补丁不能作为正文写入。

内容编辑范围不自动授权删除或移动文件；上游解析器保留这些语法，宿主明确拒绝超出本次范围的文件操作。删除文字使用 `edit` 的空 `newString` 或更新补丁中的删除行。

### 5.3 读写顺序

现有 `Agent.Run` 会并行执行同一轮工具调用，适合独立读取。文件工具在快照内加锁；实际文档修改使用串行的应用队列，在主线程进行最终校验和编辑器更新。同一文档的多个修改不能由不同 goroutine 直接写入。

提案和应用动作使用稳定标识，防止重试、重复点击和迟到响应导致重复插入。身份、范围及版本校验与内存修改处于同一次主线程操作内。

## 6. 富文本、Markdown 与结构保留

| 内容类别 | 处理要求 |
| --- | --- |
| 普通文字和行内样式 | 保留未修改部分的加粗、斜体、链接、颜色、批注等；替换部分按指令和结构片段处理 |
| 标题、列表、引用、任务项 | 保留未要求变化的层级、缩进、勾选状态及附属结构；明确要求重组时才修改 |
| 表格 | 支持单元格内容修改和明确的结构修改；校验行列、合并单元格、宽度及未修改样式 |
| 代码、公式、Mermaid | 作为对应类型的源文本处理，保留语言等属性；不经过普通段落的自动格式化 |
| 图片和附件 | 默认保留资源及引用；支持明确要求的文字说明或引用修改；不因整篇改写丢失图片 |
| 折叠块、分栏、脚注、内联注释 | 保持原有容器和关联关系；修改后验证文档模型及序列化结果 |
| 文档元数据 | 标题相关正文与 frontmatter 分别处理；未明确要求时保留图标、封面、写作目标及其他键 |
| 原样保留的未知语法 | 原样块不经普通文本改写链处理；明确进行源文本编辑时展示源文本差异，不能悄悄转换或丢弃 |

整篇编辑也应由目标操作修改需要变动的块，不把整篇文档降为纯文本后重建。未编辑的 Markdown 块继续使用现有 `ImportSource` 保留原始字节。

编辑器表面采用格式化内容时，模型上下文和预览可以使用 Markdown；最终修改仍作用于文档模型。源码视图通过同一文档身份与内容基线转换，不能另建第二个写入者。

仅对需要变更的片段进行解析和校验。合法 Markdown 解析不等于支持全部 FreeFolio 结构；必须核对修改后结构、资源和元数据是否满足上述约束。

## 7. 生成完成、保存和恢复

### 7.1 生成完成的判定

现有流式接收把非空 `finish_reason` 当作结束，未向上层保留具体原因。编辑请求必须区分正常完成、长度截断、服务拒绝、断线、取消及无法判定完成状态。

部分输出可显示和保留为草稿，但不能自动应用。空输出不代表删除；删除通过显式操作表达。重试只针对失败的生成，不重新执行已经应用的修改。

### 7.2 应用与自动保存

1. 检查任务仍有效，目标可写且没有未解决的外部文件冲突。
2. 准备修改前的恢复副本，并检查保存结果。
3. 在主线程再次校验目标的最新状态。
4. 以文档编辑事务应用选中的修改；该次应用形成一次撤销记录。
5. 通过现有保存路径落盘，继续执行外部修改检查和原子写入。
6. 分别记录“已应用”和“已保存”。保存失败时保留编辑器内容和恢复副本，提供重试。

创建文档沿用路径解析、合法文件名和原子创建能力。名称已存在时不能覆盖；返回明确冲突并让用户选择新名称或目标文档。

### 7.3 撤销与恢复

- `Ctrl+Z` / 重做继续使用文档自身的编辑历史。一批同时接受的修改形成一个撤销步骤；分次接受则按实际应用次数记录。
- 任务的回退入口只反转属于该任务、且仍满足前置条件的修改。后续手工输入不能被整篇快照覆盖；有重叠时显示冲突。
- 应用前的持久快照使用现有版本历史能力，并为 AI 修改留下可识别的恢复点。不能使用会吞掉历史写入错误的调用路径作为成功依据。
- 空间外独立文件没有现有空间历史时，恢复副本存于 FreeFolio 自身配置目录的专用位置，并通过文档身份与内容校验关联。不得向不相关目录写入隐藏空间配置。
- 重启后的恢复通过持久快照完成；未应用的候选属于草稿，退出时允许保留或丢弃。保留草稿使用带版本的本地记录，重新打开后必须重新验证目标，不自动续写文件。
- 本地记录只保存恢复和继续任务所需的内容，不复制 API Key。不得将候选或任务状态写进原文、frontmatter 或文档旁的重复格式文件。

### 7.4 多文档任务

先检查全部目标并准备恢复副本，再按顺序应用，每个文档使用既有原子保存能力。普通文件系统不提供这些文件作为整体的原子提交，因此不能承诺跨文件“全部同时成功”。

中途失败时停止未开始的应用，逐文件显示已保存、已应用未保存、失败和未执行状态。允许重试未完成部分，或按最新内容校验后回退本任务。恢复过程中出现新冲突也必须保留现状并报告。

## 8. 状态与资源管理

任务基本状态为：准备、生成、待审阅、应用中、部分应用、已应用待保存、已保存、已停止、失败、目标冲突。各候选和各文档保存各自的结果，整体状态从这些结果推导，不能由一个请求成功就宣布任务成功。

用请求代次和取消上下文过滤迟到结果。关闭文档时取消依赖该实例的自动应用；完整候选可以保留为草稿。重开文档、外部重新加载及切换空间均重新校验身份和内容。

完整文档任务按章节/块分段读取和生成，在同一任务中组装提案；超出模型上下文时说明实际覆盖范围，不能只修改开头便报告全文已完成。

限制并发、候选数量、单次响应和暂存内容的大小。流式到达只更新草稿与预览，不为每个字符克隆全文或重排全文差异。沿用现有布局缓存、帧调度和减弱动态效果设置。

## 9. 代码职责

| 位置 | 现有基础与拟新增职责 |
| --- | --- |
| `internal/agent` | 保留模型与 UI 解耦；补充结束原因、改写请求和受限编辑提案；保留现有只读检索能力 |
| `internal/document` | 目标片段、结构验证、受控修改及撤销；领域逻辑不导入 MyGo |

| `internal/history` | 复用快照和版本恢复；按需要扩展可识别的 AI 恢复点，不建立第二套文档历史引擎 |

| `internal/i18n` | 补齐中英文操作、状态、错误和无障碍文字 |

新增文件放在现有职责目录内。除非实现证明现有标准库和组件不能满足需要，不增加运行时、编辑器或网络服务依赖。

## 10. 统一验收

以下均属于交付要求，而不是后续增强列表。

| 场景 | 可观察的通过标准 |
| --- | --- |
| 选区直接改写 | 只修改捕获的目标；当前光标位置不影响结果；一次撤销恢复原文及格式 |
| 多候选 | 三个候选可比较和继续修改；切换候选不改变正文；应用正确版本 |
| 对话编辑 | 自然语言指令产生真实的对应修改；普通问答不写入文档 |
| 全文与多处修改 | 请求覆盖的范围全部处理或明确报告未覆盖部分；支持逐处和批量审阅 |
| 非目标编辑 | 等待期间改动其他段落不会误定位；目标内变动得到冲突提示且不被覆盖 |
| 重复文字 | 多处存在同样文字时，只修改本次选择的目标 |
| 分屏与生命周期 | 切换文档、关闭面板、挂起分屏、切换空间、外部重新加载后不误写 |
| 输入与字符边界 | 中文输入法、emoji、组合字符、反向选区和 UTF-16 边界均正确 |
| 富文本 | 逐项覆盖第 6 节的结构；未修改内容、资源及元数据保留；`.md` 和 `.arcmd` 均验证 |
| 部分审阅 | 接受一处后其余修改正确定位；拒绝操作不修改正文；依赖操作不能拆坏结构 |
| 取消与失败 | 停止、断线、截断、空返回、非法结构和服务错误不自动写入；迟到响应无副作用 |
| 幂等 | 重复点击、请求重试、重复工具回传不会重复插入或创建文件 |
| 保存失败 | 明确区分已修改和已保存；可重试；重试不会重复应用内容 |
| 恢复副本失败 | 不声称可恢复，也不继续自动应用；保留候选并报告具体错误 |
| 外部修改 | 写入前检测磁盘变化；冲突路径保留双方内容 |
| 撤销与重启恢复 | 撤销恢复一次应用；后续手工内容不被任务回退覆盖；重启后可找到修改前快照 |
| 多文档中途失败 | 逐文件状态准确；未开始文件不被修改；重试和回退均重新校验 |
| 只读和目标边界 | 无权限、只读、未知目标、路径越界和未被选为可写的文档得到明确拒绝 |
| 性能与可访问性 | 生成中仍可滚动和编辑非目标内容；大文档不因每个流式字符重建全文；键盘与减弱动态效果可用 |

领域测试使用真实文档和隔离文件，覆盖修改、保存与恢复行为。界面回归使用 `ui.NewTester`，网络使用本地受控响应覆盖完成、截断、取消和错误，不使用真实账号或笔记。

源码实施完成后执行项目要求的格式检查、Go 静态检查、全量测试、Windows/Linux 构建和仓库边界检查，生成 Windows x64 本地测试安装包并核对哈希与构建信息。需要真机验收时使用隔离数据和私有桌面；未验证的真机行为单独说明。

## 12. OneBot 与多供应商

- 面向用户统一命名为 OneBot，入口、设置、提示和命令保持一致，体现问答、写作、编辑与审阅的多功能助手。
- 用户可添加、命名、编辑和移除多个供应商连接，同一厂商允许配置多个独立连接。
- 获取模型后显示可搜索、可多选的列表。选择结果持久保存；支持手动添加服务没有返回的模型。
- OneBot 内可切换供应商和已启用模型，不清空已有对话。请求捕获发送时的连接和模型，后续切换不能改变正在进行的请求。
- 协议覆盖 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages、Gemini GenerateContent，以及本地 Ollama；兼容服务可选择对应协议并配置地址。
- 模型能力包括工具调用、推理、输入/输出模态、上下文和输出限制。以供应商响应优先，结合 models.dev 等公开目录；保留来源并允许手动校正，未知不能显示为已支持。
- 参数按能力和协议映射，包括输出上限、温度、推理选项。工具和格式化输出使用真实适配，不能只修改请求地址。
- 模型发现处理分页、超时、取消、鉴权失败、空列表、重复项和旧请求返回；失败不清空已勾选模型。
- API Key 继续只存凭据目录的 `ai-api-key`，使用带版本的供应商密钥集合，不迁移旧密钥，偏好中只保存连接 ID。
- OneBot 使用全新的供应商、模型和密钥关联结构，不兼容或迁移旧单供应商配置；其他应用偏好保留。新配置错误不得通过清空设置掩盖。
- 能力说明是当前提供商和目录的声明，不是模型效果保证。图片等输入在模型和协议均支持时可用；不支持的输入必须在发送前明确说明。
